## 1. スコープ: `--dry-run` を縮退版から本実装へ

現行の縮退版（`validateScript` フル検証 + `explainScript` 推定表示）を、§10.2 の**差分プレビュー**に置き換える。

### 1.1 実行モデル

* ExecutionContext を通常どおり生成し（asOf / timezone 含む）、文ループを回す。ただし:
  * **読み取り専用の文**（SELECT / CREATE TEMP TABLE / ASSERT / EXIT SUCCESS IF）は**実際に実行**する（TEMP TABLE の状態が後続 DML のプレビューに必要なため）。
  * **DML 文**（INSERT / UPDATE / UPSERT / MERGE / DELETE）は `executeStatement` の代わりに **`previewStatement`** を呼ぶ。
* `ASSERT` 違反・`EXIT SUCCESS IF` 成立は通常どおり評価し、「この時点で ABORTED / NO_DATA になる」ことを出力に表示して残りの文の処理を打ち切る。Exit Code も本実行と同じ変換（ABORTED = 2、NO_DATA = 0）を適用する — CI が dry-run でゲートできることが価値。

### 1.2 dry-run の副作用ゼロ保証（本タスクの安全要件）

* dry-run は **kintone に対して一切の書き込みを行わない**: 分散ロックの RUNNING レコードも、ログアプリの実行レコードも作らない。記録はローカル JSONL とコンソール出力のみ。
* この保証は信頼ではなく**検証**で担保する: fetch ラッパーに「dry-run 中は records 系エンドポイントへの POST / PUT / DELETE を検出したら即例外」というガードを実装し、テストでも「dry-run 実行後、ミューテーション系リクエスト数が 0 である」ことを assert する。
* 読み取りは実 API を消費するため、`limits.maxApiCalls` は dry-run にも適用する（§10.2 の既定どおり。ロック・ログ分が乗らないぶんカウンタは読取 + preview の読取のみになる）。

### 1.3 出力（§10.2 の形式を正とする）

```
[DRY-RUN] 02_calc_daily_sales.sql (as-of: 2026-08-22T00:00:00+09:00)
  読み取り        : LAPP_受注 12,340 件（API 25 回）
  書き込み予定    : LAPP_顧客マスタ  INSERT 12 件 / UPDATE 830 件 / DELETE 0 件
  実測 API 消費   : 34 回（読取 25 + preview 照合 9）
  変更サンプル（先頭 5 件）:
    顧客コード=C0012  当月売上実績: 1,200,000 → 1,450,000
    顧客コード=C0034  (新規) 当月売上実績: 380,000
```

* サンプル件数は既定 5 件、`--sample N` で変更可（上限は R2 の仕様に従う）。
* **サンプルの before / after 値には `logging.maskFields` / `stripLiterals`（§8.4）を適用する**。dry-run のコンソール出力は最もカジュアルに共有される画面であり、ここからマスク対象フィールドの実値が漏れるのは 8.4 の趣旨に反する。テスト必須。
* DELETE は削除対象のキー値サンプルを表示。
* 機械可読出力（`--json`）も併せて提供する（CI で差分を PR コメントに貼る用途、§14）。

### 1.4 run-all との組み合わせ

* `ksql run-all --dry-run` を許可する: ジョブを依存順に dry-run し、各ジョブのプレビューを連続表示する。ロックは一切取らない。ただし**ジョブ間のデータ依存は再現されない**（前段ジョブの書き込みが行われないため、後段の読み取りは現状データに基づく）ことを出力冒頭に 1 行明示する。
* この制約の明示で十分か、後段プレビューを抑止すべきかは実装時の判断が割れたら裁定へ。

## 4. 受け入れ基準

1. 設計書 3.1 のサンプルジョブの dry-run が §10.2 形式の出力を返し、その間**ミューテーション系リクエストが 0 件**（フェッチガードのテストで実証）。

4. `--sample N` / `--json` が機能する。

6. run-all --dry-run が依存順で動き、冒頭にデータ依存非再現の注意が出る。
7. 既存テスト全通過 + 本タスクのテスト追加。エンジン ^3.71.0 で CI が通る。
