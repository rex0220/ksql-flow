## 1. F-1（ASSERT 大小比較）: 報告どおりのバグ・修正済み

実測マトリクスは**全行再現**しました（起票前に両方向を独立再現）。原因は、比較の型を
**左オペランドの AST 型だけ**で決めており、スカラーサブクエリの数値性（`COUNT` 等）が
捨てられて文字列比較に落ちていたことです。`=` だけ正常に見えたのは「桁が揃うと文字列比較でも
正答する」ため — 既存テストの `BETWEEN 1 AND 500` も辞書順で偶然成立する境界でした。

修正＝**型 provenance 方式**: 両辺が数値の出どころ（数値リテラル・算術式・数値の `@変数`・
`COUNT`/`SUM`/`AVG` 等の数値集計サブクエリ）のときだけ 10 進厳密の数値比較。実値からの
推測（`Number()` 判定）はしません。

- **報告の懸念どおり `ASSERT WARN` / `EXIT SUCCESS IF` の条件部・`BETWEEN` も同一評価器で同罪でした**。すべて同時に修正済み
- **変わらないもの**: 等値・文字列同士の辞書順（`@d >= '2026-01-01'` の ISO 日付比較は従来どおり有効）・**文字列の `@変数`（CLI `--var` / MCP `variables` の外部注入は文字列型）**。外部注入した数値文字列を大小比較すると引き続き辞書順です — 数値ゲートの境界は SQL 内の数値リテラルで書くことを推奨します
- 報告書の実測マトリクス 7 行を回帰テストとして恒久化しました。**暫定回避（境界 1 桁化）は撤去できます**
- dialect 0 の素の ASSERT にも同じ修正が効きます（ASSERT 導入時からの不具合でした）。良い報告をありがとうございました — fail-open の指摘は的確で、公開レシピ R1 のゲートもこの修正で桁跨ぎに耐えるようになりました

## 2. F-2（INSERT VALUES の as-of）: 仕様案どおり実装済み

- `INSERT ... VALUES` で as-of 4 関数を受理（**dialect 1 限定・対象は 4 関数のみ**。一般式・bare 時刻関数・通常の `@変数` は引き続き拒否）
- 受入基準 3 点とも達成: ①実行 / `previewStatement` / `EXPLAIN` の **3 面で同値展開**（テストで固定）②同一バッチ内の全出現が同一 as-of ③dialect 0 は従来どおり拒否
- **スコープの明確化**: `UPSERT ... VALUES` と APPLY の値は**対象外のまま**です（報告の用途＝シード INSERT に限定。拡張が必要になったら別依頼で）。この 2 面で `@関数()` を書いた場合は**文型限定のヒント**（「INSERT ... VALUES では使用できます。この文型では INSERT ... SELECT で注入してください」相当）が出ます＝KSQL1202 小改善も同梱
- 回避策だった `INSERT ... SELECT ... LIMIT 1`（空アプリで静かに 0 件・読取 1 回消費）は不要になります
