## 確認 6 点への回答

### ① XL 相当のスクリプトに `CHECK` を付けているか → **付けていません**

検証で使った UPSERT はすべて素の `UPSERT ... SELECT` / `UPSERT ... VALUES` です（`dev/scale/scale_deal_summary.sql`・`jobs/monthly_deal_summary.sql`・`dev/seed_test_deals.sql`）。そもそも dialect 1（Flow）は `CHECK` / `VALIDATE ONLY` / `ON ERROR SKIP` を公開構文に含めておらず、業務検証は ASSERT（実行前ゲート）に寄せています。**Flow 経由の UPSERT は常に「素の UPSERT」であり、受入基準 1 は成立します。**

### ② `FlowKintoneClient` は自前実装か → **同梱 `createKintoneClient` です**

ランナーは `@rex0220/kintone-sql-tools/flow` の `createKintoneClient` をそのまま使用し（`src/runner.ts` / `src/commands/validate.ts`）、`FlowKintoneClient` は型としての import のみです。自前実装はありません。**「任意メソッドの純加法 + 実装があれば native」の設計で、当方の対応は不要になります。**

### ③ トークンにレコード追加権限はあるか → **標準運用では常にあります**

ランナーの文書（README・テンプレート README・ログアプリ手順）は書込可トークンを「**レコード閲覧 + レコード追加 + レコード編集**」で統一しており、更新専用（追加権限なし）のフローは文書化していません。したがって標準構成では権限退行は起きません。ただし利用者が独自に追加権限を落としている可能性は否定できないため、**opt-in（既定 OFF）に賛成**です。opt-in 時の権限要件（追加権限が必須になる）はランナー側ドキュメントにも明記します。

### ④ opt-in は `/flow` 限定でよいか → **ランナーとしては `/flow` 限定で十分です**

CLI / プラグインへ出すかはエンジン側の判断にお任せします（判定材料がフォーム定義で方言と直交、という整理にも同意）。

### ⑤ `onChunkWritten` の使い方 → **使っています。依存は次のとおりです**

| 用途 | 依存の強さ |
| --- | --- |
| チェックポイント（25 チャンク/60 秒スロットルでログアプリの `written_count` / `deleted_count` / `last_written_key` / `api_calls` を更新） | チャンク**通知の回数と件数**に依存 |
| ローカル JSONL への毎チャンク記録 | 同上 |
| `deleted_count` の内訳集計 | **`operation === "DELETE"` の判定に依存**（INSERT / UPDATE の区別には依存しない） |
| `last_written_key` | `lastKeyValue` を**順序保証のない診断情報として記録するだけ**。resume・復旧ロジックには不使用（公開仕様 §5.1） |

これを踏まえた希望: **①「混在を表す値を足す」案**（例: `operation: "UPSERT"`、可能なら `records` の内訳 insert/update を添える）が当方には最小変更です。DELETE でない値なら `deleted_count` 集計は正しく動き、型 union への追加のみで追随できます。**チャンクを 2 回通知に分ける案は避けたい**です（チャンク数 = 100 件単位という前提でチェックポイント頻度・進捗表示を組んでいるため）。`lastKeyValue` の意味（単一キー UPSERT でキー値を特定できる場合のみ）は現行のままで問題ありません。

### ⑥ ソースに同一キーの行が複数入り得るか → **構文上はあり得ます（保証していません）**

dialect 1 の UPSERT ソースは SELECT / VALUES で、定石は GROUP BY キー集計（この場合キーは一意）ですが、非集約 SELECT も書けるため静的には保証できません（実行時データ依存のため validate でも検出不能）。**適用条件 6（ソース内重複なしのときだけ native）は維持で構いません** — 貴側 §7 の実機確認で安全と判れば外す、の進め方に同意します。
