# kSQL Flow 実行ログアプリ テンプレート

`ksql-flow-log-template1.zip` は、設計書 8.2 の必須フィールド定義を持つ**実行ログアプリの kintone アプリテンプレート**です。レイアウトと一覧（ビュー）も設定済みで、これが最も簡単なログアプリの作成方法です。

同梱 zip は最新です: v0.3.0 で追加された任意の数値フィールド `deleted_count`（表示名「削除件数」）を収録し、2026-08-24 の更新で**レコードのタイトルを `スクリプト名` に設定済み**です（通知一覧・レコード一覧でジョブ名が見えるように。BATCH レコードのタイトルは実行対象ディレクトリ表記になります）。2026-08-27 の更新で、**リラン指示ポーラー用の `rerun_` フィールド 10 個**（`rerun_request` チェックボックス・`rerun_state` ドロップダウンほか）を収録しました。それ以前に作成した既存アプリで揃えたい場合は、アプリ設定で不足フィールドの手動追加と「その他の設定 → レコードのタイトル」の変更をしてください。**`rerun_` フィールドはランナーの動作に不要**（`--check-logapp` の検査対象外）で、無くてもランナーは従来どおり動作します — 必要になるのはポーラー（リモートからのリラン指示）を導入するときだけです。

## 使い方

1. **アプリの作成**: kintone のアプリ作成画面（スペース内に作る場合はスペースの「アプリを作成」）で「**テンプレートファイルを読み込む**」を選び、`ksql-flow-log-template1.zip` を直接指定して作成
   - システム管理のアプリテンプレートへ登録する必要はありません（繰り返し使う場合は登録しておくと便利です）
2. **API トークンの発行**: 作成したアプリの設定 → API トークン で、権限「**レコード閲覧 + レコード追加 + レコード編集**」のトークンを発行して保存
3. **config への登録**: `ksql.config.json` の対象プロファイルに追加

```jsonc
"apps": {
  "実行ログ": { "id": <作成したアプリID>, "tokens": ["env:KSQL_TOKEN_LOGS"] }
},
"logApp": "実行ログ"
```

4. **検査**: フィールド定義（`job_key` の重複禁止設定含む）が揃っていることを確認

```bash
ksql-flow validate --check-logapp --profile <profile>
```

5. **空値の保持確認**: `job_key` の重複禁止を設定したあと、**空の `job_key` を持つレコードを 2 件保存できることを確認**してください（テンプレートから作成した場合も念のため）。ロックの解放は「終了時に `job_key` を空にする」ことで成立しており、空値が複数保持できない環境では本バージョンのロック機構は動作しません（この挙動は kintone の公式ドキュメントに明記のない観測された仕様です — 破れた場合は fail-closed で全実行が停止します）

## 内容

- 設計書 8.2 の必須 22 フィールド + 任意の `deleted_count`（`record_type` / `status` はドロップダウン、`job_key` は**値の重複を禁止**設定済み — 分散ロックの前提）
- リラン指示ポーラー用の `rerun_` フィールド 10 個（ランナーの動作には不要。ポーラー導入時に使用 — 人間が触るのは `rerun_request` チェックボックスだけで、他はポーラーが書く）
- レイアウト・一覧・レコードのタイトル（= `スクリプト名`）設定済み
- 秘密情報（ドメイン・トークン等）は含まれません
- **テンプレートに含まれない設定**（ポーラーを導入する場合に手動で行う）: ①フィールドのアクセス権（`rerun_request` は依頼者グループのみ編集可・他の全フィールドは Everyone 閲覧のみ）②リマインダーの条件通知（更新日時 + 1 時間・`rerun_request` に REQUEST を含む かつ `rerun_state` 未選択）— いずれも環境のグループに依存するため

## 代替手段

- `ksql-flow init-logapp --profile <p>`: kintone アプリ作成 API による自動生成（**password 認証プロファイルが必要**。テンプレートが使えない環境向け）
- 既存アプリの流用: フィールドを 8.2 に合わせた上で `--check-logapp` で検査
